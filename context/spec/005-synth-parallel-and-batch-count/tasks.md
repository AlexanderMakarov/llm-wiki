- [x] **Slice 4: Pages are synthesized in parallel with visible progress**

  > The core of the change — FR2, FR4, and the `(N at a time)` half of FR1. Depends on Slices 2 and 3.
  - [x] Extract the per-source body of the `for it in new_items:` loop in `llmwiki/synth/pipeline.py` into a module-level `_synthesize_one(item, *, backend, prompt_template, sources_out, chunk_max, write_lock) -> dict`. The worker must be **pure with respect to shared state**: it chunks the body, calls `backend.synthesize_source_page` per chunk, builds and writes that source's page(s), and returns a record `{rel, mtime, project, is_doc, meta, slug, written: list[str], protected: int, error: str | None}`. It must not touch `state`, `summary`, or `producers`, and must not print. It catches `Exception` and returns the message in `error` so one bad source cannot tear down the drain. Behavior is otherwise byte-for-byte what the loop does today. **[Agent: general-purpose]**
  - [x] Inside `_synthesize_one`, serialize the *read-existing → decide → write* sequence for each page under the passed `write_lock` (a single module-level `threading.Lock` created per run): `_build_source_page(..., existing_page_path=out_path)` reads the target to preserve maintainer-curated tags (#351), and the stub guard reads it again to decide whether to withhold a placeholder. Two sources in one batch can derive the same target filename (same project, date, and normalized slug — the collision G-06/#292 guards against), and an unguarded read-modify-write there can produce a torn page. Hold the lock only for that cheap file I/O, never across the backend call. **[Agent: general-purpose]**
  - [x] Replace the loop in `synthesize_new_sessions` with a `concurrent.futures.ThreadPoolExecutor(max_workers=concurrency)` submitting one `_synthesize_one` per item, drained with `as_completed`. **Every shared mutation stays in the main thread**, inside the drain: print each written page as `  [k/N] synthesized: <project> → <name>`, add `result["protected"]` into `summary["protected"]` (printing the existing `protected:` message with the same `[k/N]` prefix), and on success set `state[rel] = mtime`, call `_save_state`, apply the `_drop_pending` unified-state update, increment `summary["synthesized"]`, and tally `producers`; on error append to `summary["errors"]`, increment `summary["skipped"]`, and print `  [k/N] error: <slug>: <message>`. `k` counts **completed sources** and `N` is the queue size, so a chunked doc's part-pages share one position and the final `k` always equals `N`. Skip the executor entirely when the queue is empty. Everything after the drain — the single `_append_log`, the final `_save_state`, `refresh_synth_pending`, the `synthesized > 0`-gated `_rebuild_index`, and `take_usage()` — is unchanged and still runs exactly once. **[Agent: general-purpose]**
  - [x] Handle `KeyboardInterrupt` in the drain: `ThreadPoolExecutor.__exit__` calls `shutdown(wait=True)`, so a bare Ctrl-C would block silently until every in-flight page finished — worse than today, where it stops after the current page. Catch it, call `shutdown(wait=False, cancel_futures=True)`, print how many in-flight pages are being waited on, then re-raise. Sources completed before the interrupt already have their state saved, so a re-run picks up exactly the remainder. **[Agent: general-purpose]**
  - [x] Render the concurrency in the start line from Slice 1 — `Synthesizing <N> source(s) with <backend> (<C> at a time)` — and pass the resolved value from `synthesize_new_sessions`. This completes FR1. **[Agent: general-purpose]**
  - [x] Extend `tests/test_synth_parallel.py`: (a) **parallelism is real, proven deterministically without sleeps** — a fake backend that waits on a `threading.Barrier(2)` with a short timeout succeeds at `concurrency=2` and times out at `concurrency=1`; plus a fake recording concurrent entries/exits asserting peak in-flight `> 1` at 4 and exactly `1` at 1. (b) **Equivalence, the core FR2/FR5 guarantee** — the same fixture corpus run at `concurrency=1` and `concurrency=4` yields identical page paths, identical page contents, identical `summary` counters (`synthesized`, `skipped`, `protected`, `new_files`, `total_scanned`), an identical producers breakdown in the log entry, and identical resulting synth state. (c) **Progress counter** — every result line carries `[k/N]`, the final `k` equals `N`, error lines carry a position too; assertions must be order-independent. (d) **Failure isolation** — one source's backend raises, the rest still complete, the error is recorded, `skipped` increments, and the failed source's key is **absent** from synth state so a re-run retries exactly it. (e) **Stub protection under concurrency** — an existing real page plus a placeholder-producing backend leaves the real page byte-identical and increments `protected`. (f) `_append_log` fires exactly once per run and `_rebuild_index` stays gated on `synthesized > 0`. **[Agent: general-purpose]**
  - [x] Audit and repair the existing test suite for the new `[k/N]` prefix: sweep `tests/test_synth_*.py`, `tests/test_synthesize_*.py`, and `tests/test_exclude_headless_synthesis.py` for assertions on exact `synthesized:` / `error:` / `protected:` stdout, update them, and rewrite any assertion that depends on the *order* of per-page output to assert on sets instead — output order is no longer deterministic above `concurrency=1`. **[Agent: general-purpose]**
  - [x] Verify: from the worktree, seed a scratch vault with several synthetic raw sessions, run `python3 -m llmwiki synth --sources-only --vault <scratch>` and confirm the start line reports the count and `(2 at a time)` and that each page line carries `[k/N]` ending at the announced total; re-run with `--concurrency 1 --force` and confirm identical pages are produced. Run `ruff check llmwiki tests scripts` and the full `python3 -m pytest tests/ -q`. Delete the scratch vault when done. **[Agent: general-purpose]**
