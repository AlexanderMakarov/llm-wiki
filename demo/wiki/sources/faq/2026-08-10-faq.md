## Summary

The FAQ clarifies llmwiki's design principles and capabilities: local-only operation with no external telemetry or API dependencies (except optional local Claude binary for synthesis), support for 7 agent adapters (Claude Code, Codex CLI, Copilot Chat/CLI, Cursor, Gemini CLI, Obsidian), and a three-tier storage model (`raw/`, `wiki/`, `site/`) that implements layer 2 of Karpathy's LLM Wiki spec. Key features include multi-agent coordination on shared wikis, offline-capable builds, and AI-ready exports (llms.txt, JSON-LD, RSS).

## Key Claims

- No telemetry, no external API calls, no network requests except optional local Claude binary (for `--synthesize`) and CDN-loaded highlight.js for syntax highlighting
- Supports 6 production agents (Claude Code, Codex CLI, GitHub Copilot Chat/CLI, Obsidian) plus 2 scaffolded adapters (Cursor, Gemini CLI)
- Data persists in three gitignored directories: `raw/` (session transcripts), `wiki/` (agent-maintained pages), `site/` (generated HTML)
- Wiki layer implements layer 2 of Karpathy's spec with subsections: `sources/`, `entities/`, `concepts/`, `projects/`, `syntheses/`
- Multiple agents can write to the same wiki without collisions via separate adapter namespaces and registry names
- Requires Python 3.12+; only external dependency is the `markdown` package
- Exports to 6 formats: llms.txt, llms-full.txt, graph.jsonld, sitemap.xml, rss.xml, and Obsidian vault sync

## Key Quotes

> "Everything runs locally. There is no telemetry, no analytics, no phoning home."

Establishes the privacy guarantee and offline-first design.

> "The wiki layer implements layer 2 of [Karpathy's LLM Wiki spec](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f). While `raw/` holds immutable session transcripts and `site/` holds generated HTML, `wiki/` is maintained by your coding agent"

Clarifies the three-layer architecture and which components are mutable vs. immutable.

> "Each agent produces sessions with its own adapter name and project slug, so there are no collisions in `raw/sessions/`. The wiki layer (`wiki/`) is agent-agnostic -- entities and concepts from different agents merge naturally."

Explains how multi-agent federation works without conflicts.
