## Summary

This document (Part 1 of 2) establishes [[llmwiki]]'s privacy architecture: secrets (API keys, tokens, passwords, emails) are redacted by default at the converter layer before data reaches `raw/`, while username redaction is configurable and off by default to preserve usable paths in private vaults. The design enforces several non-negotiable rules (no server, no telemetry, no network by default, and gitignored output directories) and provides migration tools to toggle username redaction retroactively across existing converted sessions.

## Key Claims

- Secret redaction (API keys, tokens, passwords, emails) is ON by default and runs at the converter layer before files hit `raw/`.
- Username redaction is OFF by default so private vaults keep real home paths (`/home/<you>/…`); toggled via `"redact_username"` in `config.json`.
- [[llmwiki]] ships no server; the built site consists only of static files you open in a browser.
- No telemetry: the tool never calls home, never sends usage counts or error reports.
- All output directories (`raw/`, `wiki/`, `site/`, `.ingestion-state.json`) are gitignored and never enter version control.
- A `tests/test_privacy_username.py` guard fails the suite if the maintainer's real username appears in tracked `.md` or `.py` files.
- Gitleaks CI scanning blocks merges on any detected API key, token, or password.
- File paths outside the home directory (e.g., `/opt/foo`, `/var/log/bar`) are NOT redacted by default.
- Text content pasted into user prompts (including passwords or contracts) is NOT redacted by default because the prompt IS the signal.
- Custom redaction patterns can be added to `config.json` under `redaction.extra_patterns`.
- Running `llmwiki migrate raw-redaction --vault PATH` rewrites already-synced `raw/` files to apply username redaction without re-converting or re-synthesizing.

## Key Quotes

> "Secret redaction is ON by default. API keys, tokens, passwords, and emails are redacted before anything hits `raw/`." — Core enforced behavior at the converter layer.

> "Nothing listens. llmwiki ships no server; the built site is files you open in a browser." — Local-first, no listening endpoint.

> "No telemetry, ever. The tool never calls home." — Privacy by design, no usage tracking.

> "raw/ is gitignored and nothing llmwiki produces is served anywhere." — Why unredacted content is safe to keep locally.

> "This is why `raw/` is gitignored and nothing llmwiki produces is served anywhere." — Reinforcement of the data confinement model.
