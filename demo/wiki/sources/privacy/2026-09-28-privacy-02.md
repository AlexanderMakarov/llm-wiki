## Summary

This document explains [[llmwiki]]'s privacy model, emphasizing offline-first design with one opt-in exception: the `--synthesize` flag. By default, all data remains local; synthesis only transmits aggregated project metadata (no content) to generate a homepage overview, and only when explicitly requested.

## Key Claims

- The `--synthesize` flag is the only feature that sends data off-machine; synthesis is opt-in and off by default.
- Synthesis sends only a JSON summary of projects (names, session counts, dates, models) to the local `claude` binary — never transcript content.
- The built site is completely static with no server; all scripts and stylesheets are bundled at build time.
- The generated site functions identically whether opened offline or online, with no reachability from the network.
- The GitHub Pages demo workflow deploys using a synthetic corpus in `demo/`, never real session history.
- Incident response for accidental PII or secrets involves history rewriting with `git filter-repo` and immediate credential rotation.

## Key Quotes

> "llmwiki ships no server. The built site is a directory of files you open in a browser, and every script and stylesheet it loads — including the code-highlighting library and its themes — is written into `site/` at build time. Opening it offline gives the same result as opening it online, and no process of yours is reachable from the network."

This encapsulates the core privacy guarantee: the system is self-contained, offline-capable, and unreachable from the network.

> "Even this is off by default. You have to pass `--synthesize` explicitly. If you don't want any external API calls, just don't pass the flag — the home page still renders with project cards and stats, just without the synthesis paragraph."

This illustrates how synthesis is a deliberate opt-in exception, preserving user control over external calls.
