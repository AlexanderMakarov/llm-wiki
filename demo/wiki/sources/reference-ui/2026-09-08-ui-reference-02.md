## Summary

This reference slice documents four areas of the built static wiki UI: the **Candidates** review gate at `/candidates.html` (pending entity/concept stubs with per-row decisions that batch into `llmwiki candidates apply`), the **Projects** grid and per-project detail pages (session counts, freshness, topic chips, connected topics, heatmaps), the **Sessions** index and detail views (filters in `sessionStorage`, activity sparkline, synthesized summary and downloadable source markdown), and the **Models** catalog driven by `ModelProfile` in `llmwiki/schema.py`. The Candidates page is explicitly designed so browser state never mutates the vault until Apply runs the CLI (with optional `--no-rebuild` for multi-batch workflows).

## Key Claims

- The Candidates **Decision** column offers exactly the four actions `llmwiki candidates apply` supports: promote, flip-promote, merge, and discard; rows at **No decision** are omitted from the batch so partial reviews can be applied and resumed.
- **Merge into…** uses a closed, filterable target list (trusted `wiki/<kind>/` pages first, then same-table pending stubs); invalid free text is surfaced on the page instead of being sent in a batch that would fail at the CLI.
- **Discard** requires a non-empty reason; without it the row is held back like an unresolved merge target, because `discard` archives the reason beside the stub.
- Successful `llmwiki candidates apply` rebuilds `site/` by default; `--no-rebuild` is for applying several batches before a single `llmwiki build`.
- Project **created** and **updated** on project detail pages are the min and max session `date` values recomputed at build time—project stubs carry no dates themselves.
- **Connected topics** on project detail is omitted entirely (heading included) when the project’s topic node has no connections or when the vault has too few topics for the topic graph to be used.

## Key Quotes

> "Every row starts at **No decision** and stays there until you choose — deciding is browser state, so nothing runs and nothing is sent." — Defines the review gate as preview-only until Apply.

> "The list is the closed set of valid targets: text naming no page is marked as you type, and a row holding one is named on the page instead of going into a batch that would fail at the CLI." — UI validation mirrors CLI merge resolution.
