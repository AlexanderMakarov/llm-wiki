## Summary

Documents the CLI interface and semantics for [[llmwiki]]'s `install-automation` command, covering exit codes (0/1/2), wrapper script logging behavior, and the structure of the automation status file. Specifies three supported scheduler backends (systemd, launchd, schtasks) and their metadata fields.

## Key Claims

- Exit code `0` indicates scheduler files were written and either activated or skipped due to user refusal; vault and config remain unchanged.
- Exit code `1` signals scheduler activation failure; the status file records `scheduler_error`.
- Exit code `2` means the schedule expression cannot be translated by llmwiki.
- Wrapper scripts log the actual command exit code in format `EXIT:<code>` and exit with that same code, enabling diagnostic separation of usage-limit stops (code 75) from failures (code 1).
- Older wrapper scripts always logged `EXIT:0` and must be regenerated by re-running `install-automation`.
- Status file is located at `<vault>/.llmwiki/automation-status.json` and includes fields: `scheduler_activated` (bool), `scheduler_backend`, `scheduler_units_dir`, `scheduler_active`, and `scheduler_error`.

## Key Quotes

> "The installed wrapper script ends its log with `EXIT:<code>`, the scheduled command's real exit code, and exits with that same code — so the scheduler can tell a usage-limit stop (`75`) from a failure (`1`)."

— Explains how real exit codes are preserved and distinguishes scheduler errors from user-triggered stops.
