## Summary

This tutorial teaches the first sync workflow in [[llmwiki]], which ingests JSONL session transcripts and generates a browsable static wiki site. The walkthrough covers four steps: status verification (read-only), running sync, serving the site locally, and optionally previewing costs before synthesis. The result is a searchable, graphable wiki with project grouping, activity heatmaps, and a command-palette search interface. Emphasis is placed on the immutable-mutable-browsable three-tier directory structure and safe verification modes that commit no data.

## Key Claims

- llmwiki ingests JSONL transcripts from multiple adapters in a single `sync` invocation, applying ingest filters and auto-building the static site in one pass
- The `--status` flag provides a read-only preview of what the sync would record (last sync time, per-adapter counters, quarantined sources) without writing any data
- The sync creates three directory tiers with distinct semantics: `raw/` (immutable, never hand-edited), `wiki/` (editable, contains agent output), and `site/` (browsable static HTML)
- Cost estimation via `synth --estimate` precomputes API costs using a rate card in `llmwiki/cache.py` without making any actual API calls; actual usage comes back in the `usage` field of each API response
- The generated site includes a home page with project grid and activity heatmap, individual project cards with freshness badges, a sortable sessions table, an interactive force-directed knowledge graph, and a Cmd+K fuzzy-search command palette
