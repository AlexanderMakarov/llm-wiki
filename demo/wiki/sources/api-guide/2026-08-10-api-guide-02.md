## Summary

Part 2 of the API Guide showcases practical automation examples for the llmwiki Python library. Two working scripts are provided: a custom pipeline (sync → build → export) and an adapter discovery tool. The guide documents key guarantees: idempotent session syncing via state tracking, deterministic builds, and vault configuration through `config.json` instead of environment variables.

## Key Claims

- `convert_all` is idempotent—state is tracked in `llmwiki-state.json` (path from `configure_state_file` or `resolve_state_file`)
- `build_site` is deterministic—identical inputs produce identical outputs
- All public functions are importable directly from their module paths
- No function requires network access except `image_pipeline.process_markdown_images` with `--download-images`
- Content root is read from `vault.default_path` in `config.json` (or explicit `state_file` parameter); the `LLMWIKI_ROOT` environment variable is no longer read

## Key Quotes

> "`convert_all` is idempotent -- state is tracked in `llmwiki-state.json`" — guarantees safe repeated execution without re-processing

> "Content root comes from `vault.default_path` in `config.json`... The removed `LLMWIKI_ROOT` env var is no longer read." — clarifies the shift from environment variable to configuration file for vault paths
