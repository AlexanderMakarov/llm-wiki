## Summary

Part 1 of the API Guide documents using [[llmwiki]] as a Python library in custom scripts and pipelines. It covers five core functions (`convert_all`, `build_site`, `serve_site`, `build_and_report`, `export_all`), the adapter registry, and helper modules for visualization, freshness checks, model/project discovery, and export formats.

## Key Claims

- `convert_all()` is the programmatic equivalent of the `llmwiki sync` CLI command, discovering agent session stores and converting `.jsonl` files to markdown.
- `build_site()` reads from both `raw/` and `wiki/` directories and compiles a static HTML site (equivalent to `llmwiki build`).
- Adapters are discoverable and directly usable via `REGISTRY` after calling `discover_adapters()`.
- Visualization helpers (`render_heatmap`, `render_session_tool_chart`, `render_session_token_card`) consume metadata from session frontmatter.
- `export_all()` generates multiple AI-consumable formats: `llms.txt`, `llms-full.txt`, JSON-LD, sitemap, RSS, and robots.txt.

## Key Quotes

> "The `llmwiki` package exposes several functions that can be imported directly" — establishes programmatic use as a first-class interface alongside the CLI.

> "This is the programmatic equivalent of `llmwiki sync`" — indicates functional parity between Python API and CLI for pipeline integration.
