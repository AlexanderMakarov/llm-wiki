## Summary

This reference document defines the three page kinds in LLM Wiki: `entity` (persons, products, tools), `concept` (ideas, frameworks, methods), and `project` (codebases, work streams). It specifies which fields are written by the harvest stub-generation process, which are human-filled, how candidates are promoted to published pages, and which fields are conventionally absent from each type.

## Key Claims

- Harvest automatically creates candidate stubs when 3 or more source pages reference the same target, folding case/punctuation variants into one canonical spelling (#204)
- Fields written by harvest (`title`, `type`, `status`, `sources`, `last_updated`) are preserved unchanged during promotion; the promote step fills `## Key Facts` from source topic `fact:` bullets offline without calling a synthesis backend
- Entity pages with `entity_kind: ai-model` are indexed in `/models/`; all model profile fields (`provider`, `pricing`, `modalities`, `benchmarks`) are human-written only (no producer writes them)
- Project stubs are generated by `ensure_project_stubs()` during `build --seed-project-stubs` or `sync`, and use `topics:` (not `tags:`) for metadata
- Entity and concept pages conventionally omit `source_file`, `date`, `project`, and `model` fields—those belong on source pages, not on the entities/concepts they spawn

## Key Quotes

> "Harvest writes a stub under `wiki/candidates/entities/` when enough source pages name the same target (default three), folding case/punctuation variants (`[[LLMWiki]]` / `[[llmwiki]]`) into one stub under the dominant spelling"
— Describes the deduplication and stub-creation logic

> "Promote keeps those fields, fills an empty `## Key Facts` from source topic `fact:` bullets offline (no synthesis backend required)"
— Clarifies that promotion is deterministic and local, not a synthesis API call

> "An entity with `entity_kind: ai-model` is picked up by the `/models/` index. Every field below is **human** — no synth, harvest, or build path writes them."
— Establishes the opt-in model profile as a human-only schema extension
