## Summary

This reference documents three page kinds in [[llmwiki]]: `synthesis` (human-authored saved answers), `navigation` (infrastructure machinery like index and log), and `context` (folder metadata stubs). It specifies which producers write each kind's frontmatter and establishes conventions—particularly that no pipeline generates synthesis pages, certain navigation files lack frontmatter, and three metadata fields are never pipeline-written.

## Key Claims

- No pipeline process generates synthesis pages automatically; only humans author pages in `wiki/syntheses/` and `wiki/overview.md`
- `llmwiki init` seeds `overview.md` with `type: synthesis`, empty `sources`, and empty `last_updated` fields
- Navigation pages are infrastructure, not user-searchable content; lint exempts `index.md` and `log.md` from frontmatter requirements by filename
- Context stubs (`_context.md` files) are manually created to label folders and help agents understand scope; they are never auto-generated
- Three fields—`confidence`, `lifecycle`, and `last_verified`—are never written by any producer and exist only when humans add them
- The `status` field is unique: only the harvest process and promote command touch it (harvest writes `candidate`, promote rewrites to `reviewed`)

## Key Quotes

> "Nothing in llmwiki generates a synthesis page automatically."
— Establishes that synthesis pages are strictly human-authored, not pipeline-generated.

> "Machinery, not a kind anyone searches for. Search still reaches these pages when unfiltered; the kind is omitted from the kind filter."
— Defines navigation as infrastructure machinery, not user-searchable content.

> "The context parser is key/value only — no lists, no nested JSON."
— Specifies the lightweight constraint on _context.md metadata.

> "These names appear in the code… but no synth, harvest, or build path writes them."
— Confirms that confidence, lifecycle, and last_verified are never pipeline-written.
