## Summary

This reference documentation (part 1 of 4) covers the 12 slash commands in the [[llmwiki]] vault pipeline and establishes key design patterns. It distinguishes when to use slash commands (for model-driven workflows in [[Claude Code]]) versus CLI (for scripts and CI), and defines lint as the unified quality-checking tool.

## Key Claims

- The vault pipeline consists of exactly 12 commands that process raw documents into static wiki sites in a defined sequence (`/wiki-init`, `/wiki-sync`, `/wiki-ingest`, `/wiki-synth`, `/wiki-candidates`, `/wiki-query`, `/wiki-update`, `/wiki-lint`, `/wiki-graph`, `/wiki-reflect`, `/wiki-build`, `/wiki-all`)
- Slash commands are designed for use inside [[Claude Code]] with outputs fed back to the model for chaining; CLI (via `python3 -m llmwiki`) is for shell scripts, CI jobs, and programmatic piping
- Lint consolidates all quality checks (frontmatter, wikilinks, orphans, duplicates, staleness, cache consistency); no separate eval command exists
- Maintainer commands (`/maintainer`, `/release`, `/triage-issue`, `/fix-bug`, `/implement-feature`) are excluded from agent kit installation and documented separately

## Key Quotes

> "If the output is for *you* to read + act on manually, use the CLI. If the output should feed back into an LLM turn, use the slash — the model sees the full stdout and can chain into the next step."

Defines the fundamental design split: slash commands enable LLM-driven workflows; CLI enables scripting and automation.

> "Reach for lint when a page or the corpus looks wrong: orphans, broken `[[wikilinks]]`, missing frontmatter, stale summaries."

Establishes lint as the single unified quality tool across all wiki quality dimensions.
